# Platform checks (milestone 49)

Godot exports to Windows, Linux (x86_64 and arm64), macOS, Android, iOS and the web. FellowEngine was developed and
measured on one Windows laptop with an NVIDIA GPU; these scripts check the other platforms on one x86_64 Linux machine,
with containers, emulators and Mesa's software drivers, without the hardware (decision 0150).

| what | how | script |
|---|---|---|
| Godot's three renderers (Forward+, Mobile, Compatibility) on every bench lab | lavapipe (Vulkan) and llvmpipe (OpenGL) | `renderer_matrix.sh` |
| weaker and other GPUs: Android baselines, Intel, AMD, older NVIDIA, Apple through MoltenVK | `FELLOW_VULKAN_PROFILE` in the Vulkan driver (below) | `renderer_matrix.sh` with `PROFILE=` |
| Windows x86_64 export template | MinGW-w64 in a container | `platforms.sh build windows` |
| the Windows build running | Wine, with lavapipe behind winevulkan | `platforms.sh shell wine ...` |
| Linux arm64 export template | GCC's aarch64 cross-compiler in a container | `platforms.sh build linux-arm64` |
| the arm64 build running | qemu-user: headless with the cross-compiler's libraries, rendering with Ubuntu's arm64 Mesa (lavapipe, llvmpipe) | `platforms.sh shell cross qemu-aarch64 -L /usr/aarch64-linux-gnu ...`, `shell arm64 qemu-aarch64 -L / ...` |
| Android and web export templates | the Android NDK and Emscripten (downloaded toolchains; built in milestone 50) | `platforms.sh build android`, `build web` |
| the web template running | headless Chromium (Playwright's; WebGL 2 on SwiftShader), a `.pck` packed by a desktop build, a server with the cross-origin isolation headers the threads need | `web/web_check.sh <template zip> <desktop godot> <out>` |

`platforms.sh image <cross|wine|arm64|android|web>` builds the container images (`Dockerfile.*`; Ubuntu 24.04 packages,
plus the NDK from Google and emsdk from GitHub for the last two). Builds run in a copy of the repository
(`$FELLOW_PLATFORMS_TREE`, rsync) so that the containers' SCons keeps its own objects and generated sources (the
host's `*.gen.*` are not copied: an older copy of another platform's would not be regenerated).

## Simulated GPUs: FELLOW_VULKAN_PROFILE

`FELLOW_VULKAN_PROFILE=<name>` makes the Vulkan driver present its device as another one: the extensions, features and
subgroup operations the other device lacks are hidden and its limits are clamped, so Godot and FellowEngine choose the
paths they would choose there; every shader is then checked against it, and what the device could not run is printed
once as `FELLOW_PORTABILITY <profile>: <shader> ...` (capabilities it lacks, workgroups and shared memory beyond its
limits, descriptors beyond its per-stage limits, uniform buffers beyond its range). The device profiles are generated by
`make_vulkan_profiles.py` from the Khronos Vulkan-Profiles repository (Android's profiles, and device captures from
vulkan.gpuinfo.org) into `drivers/vulkan/fellow_vulkan_profile_data.h`:

| profile | stands for |
|---|---|
| `android_2022`, `android_2025` | Android's Vulkan profiles (what Android devices of that year are guaranteed to have) |
| `intel_uhd620`, `intel_arc_a770` | Intel's laptop iGPU of 2017-2020, Intel's discrete GPU |
| `gtx1060`, `rtx4070` | NVIDIA Pascal (no ray tracing, no fp16 arithmetic), NVIDIA Ada |
| `rx580`, `rx7800xt` | AMD Polaris (no ray tracing), AMD RDNA 3 |
| `apple_m1` | Apple's M1 through MoltenVK |
| `no_ray_tracing`, `no_float16`, `subgroup_basic` | the device with one family of features removed |

Not simulated: the subgroup's size (shaders run with the device's), performance, memory sizes, and driver bugs.
A profile can only take away: lavapipe has no cooperative matrices, so nothing needing them runs under any profile.
